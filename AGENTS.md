# Reglas para agentes

Este archivo lo leen Codex y otros agentes. Claude Code lo carga desde [CLAUDE.md](CLAUDE.md).
Vale para cualquier persona o agente que cambie este repositorio.

HHR es la aplicación clínica del Hospital Hanga Roa, en Rapa Nui. Producción trabaja con datos
reales de pacientes.

## Antes de cambiar algo

Este archivo basta para empezar: la tabla de abajo resume las reglas. Lee además **solo** lo
que corresponde a lo que vas a tocar; el resto de `docs/` es de consulta, no lectura previa.

| Si el cambio…                                                             | Lee                                                                                                                                                                  |
| ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| es un texto, un estilo o una constante                                    | Nada más. Si la constante figura en una regla de este archivo, actualiza su fila.                                                                                    |
| toca datos clínicos, identidad, hora, guardado, sincronización o permisos | La regla, por su identificador (ID-01, TIME-02, SAVE-01…), en el [contrato operativo](docs/DOMAIN_RULES.md). El contrato manda sobre el código y sobre este archivo. |
| crea un módulo, mueve una responsabilidad o cruza features                | «Elegir dónde cambiar» en [CONTRIBUTING.md](CONTRIBUTING.md) y el README de la carpeta.                                                                              |
| pertenece a un área con diseño propio                                     | Ese diseño en `docs/`. Por ejemplo, la fase 1a: [DESIGN_DAILY_RECORD_PHASE1_CLINICAL_DERIVED.md](docs/DESIGN_DAILY_RECORD_PHASE1_CLINICAL_DERIVED.md).               |
| falla en CI                                                               | El control que falló en [CI y recuperación](docs/CI_GATES_AND_FAILURE_RUNBOOKS.md), no el documento entero.                                                          |
| usa un término del hospital que no entiendes                              | Ese término en el [glosario](docs/GLOSSARY.md).                                                                                                                      |

Un merge a `main` llega a producción. Netlify publica solo y CI despliega Functions.

## Reglas y qué las hace cumplir

Cada fila dice qué impone la regla. **[docs]** marca las que solo dependen de que el agente
lea este archivo.

Se conserva la forma con más diacríticos y, en empate, la ya catalogada. ### Guardado y sincronización

| Regla                                                                                                                                                                                                                                                                                                                                                                                          | Qué la impone                                                                                                                                                                                             |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ninguna reparación, cierre de sesión o reinicio borra la cola, los parches pendientes ni el outbox sin confirmación explícita. Descartar un censo bloqueado conserva un respaldo descargable y no cuenta como guardado remoto (SAVE-03).                                                                                                                                                       | Pruebas de arranque y de cola; **[docs]** para rutas nuevas                                                                                                                                               |
| Una corrida clínica se detiene si cambia el propietario o la generación de sesión. Conserva lo confirmado y la cola durable; una corrida interrumpida exige una captura nueva, sin reanudación ni avisos de sesión. La edición local en vuelo conserva propietario, base y contexto en reposo, aunque la cola activa siguiente esté llena; revierte la vista sin avisar a la sesión siguiente. | Pruebas de cambio de sesión del lote, CUDYR histórico, archivo y auditoría; `inFlightEditOwnerRetention.test.tsx`; sesión obligatoria en contratos internos y `dailyRecordPort.authoringBoundary.test.ts` |
| Compartir o marcar una entrega médica conserva el día de origen en cada mutación, aunque cambie el censo visible; un envío realizado se informa también después de navegar.                                                                                                                                                                                                                    | Pruebas de envío y cambio de día                                                                                                                                                                          |
| En el reenvío, solo el valor almacenado acredita un campo ya aplicado; un valor igual por hidratación se envía. Las rutas ya aplicadas no generan conflictos por metadatos, y un conflicto real conserva la tarea completa sin escritura.                                                                                                                                                      | Pruebas de emulador en `offlineReplayEquivalence.emulator-ui.test.ts`                                                                                                                                     |
| Nunca purgar una cola por antigüedad ni por número de fallos.                                                                                                                                                                                                                                                                                                                                  | **[docs]**                                                                                                                                                                                                |
| El cambio de sesión de Eloísa se observa solo con `onSessionChange` o `useSessionEpoch` (`src/services/storage/sessionStorageTransition.ts`). Nadie escucha el mensaje `HHR_RAYEN_SESSION_CHANGED` en la app: lo que recuerda algo por persona lo olvida ahí, esté o no montado.                                                                                                               | ESLint `no-restricted-syntax`; pruebas de `sessionChangeScope`                                                                                                                                            |
| Una lectura fallida no es «sin datos», tampoco en suscripciones: conservar lo último conocido y señalar el fallo por su canal de error. Una escritura fallida no es «guardado» (SAVE-01). El control no admite excepciones heredadas; solo capacidades opcionales del navegador con motivo junto al retorno.                                                                                   | `npm run check:empty-on-failure-reads` en la capa de datos y laboratorio; **[docs]** fuera de ellas                                                                                                       |
| La decisión manual de especialidad reintenta una vez la lectura local; si sigue fallando usa solo la base explícita del llamador bajo CAS y confirmación remota obligatorios. Nunca confirma una decisión rechazada ni inventa ausencia local.                                                                                                                                                 | `usePatchDailyRecordLocalReadRecovery.test.tsx`; pruebas de especialidad                                                                                                                                  |
| Los documentos `clinicalDerived` de la fase 1a los escribe solo el servidor. No cambiar `HHR_CLINICAL_DERIVED_SPLIT_FROM` sin el responsable.                                                                                                                                                                                                                                                  | `firestore.rules`; **[docs]**                                                                                                                                                                             |
| La atribución del diagnóstico local usa el propietario admitido en memoria por esta pestaña, nunca la clave compartida. Sin admisión no se atribuye; fallar el almacenamiento no interrumpe el envío. Solo el administrador conserva el historial del equipo en Errores locales.                                                                                                               | `localDiagnosticsOwnership.test.tsx`; mutaciones de propietario, rol y envío                                                                                                                              |

### Código y dependencias

| Regla                                                                                                                                                                                    | Qué la impone                                                                                                                                                                               |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| El código de producción de `src/` no usa `any` explícito.                                                                                                                                | ESLint (`@typescript-eslint/no-explicit-any` como error)                                                                                                                                    |
| Todo paquete importado está declarado en `package.json`.                                                                                                                                 | `npm run check:declared-dependencies`                                                                                                                                                       |
| No hay ciclos de imports en tiempo de ejecución.                                                                                                                                         | `npm run check:import-cycles`                                                                                                                                                               |
| Todo módulo de la app se alcanza desde un punto de entrada. Lo que se conserva sin uso figura, con su motivo, en `scripts/config/unreachable-modules.json`.                              | `npm run check:unreachable-modules`                                                                                                                                                         |
| Un feature importa otro solo si `scripts/feature-dependency-matrix.json` lo permite, y solo por su superficie pública (`public.ts`, `index.ts` o un módulo de `publicModulesByFeature`). | ESLint (`hhr/feature-boundaries` desde la matriz y `hhr/public-import-boundaries` para consumidores externos y capas compartidas); paridad carpetas↔matriz en `featureBoundaryLint.test.ts` |
| Los tipos del dominio se importan de su hogar en `src/types/domain/*`; las formas estrechas llevan nombre propio, sin alias puros ni reexportaciones por capa.                           | `npm run check:repo-hygiene`                                                                                                                                                                |
| Los módulos son cohesivos y tienen como máximo 600 líneas.                                                                                                                               | `npm run check:module-size`                                                                                                                                                                 |
| Las dependencias de la raíz y de Functions pasan la auditoría sin hallazgos altos ni críticos, y sin excepciones aceptadas.                                                              | `scripts/check-dependency-vulnerabilities.mjs` en `security-audit.yml`                                                                                                                      |
| Sin reescrituras, plataformas ni colas nuevas. Un cambio de rendimiento necesita una etapa y una causa medidas.                                                                          | **[docs]**                                                                                                                                                                                  |
| No borrar `Formularios/` ni `Hospital Salvador/`. Preguntar antes de tocar `printables/` o los PNG de la raíz.                                                                           | **[docs]**                                                                                                                                                                                  |

## Mantener esta tabla

- Cuando el responsable corrige a un agente, arreglar el error y agregar aquí la regla.
- Si la regla ya estaba y nada la hacía cumplir, el error es una repetición. En el mismo
  cambio, imponerla al nivel más alto que funcione y actualizar su fila. El orden es:
  arquitectura, tipos, un control cuyo error nombre el arreglo, una prueba.
- Quitar una regla cuando su error ya no puede ocurrir.
